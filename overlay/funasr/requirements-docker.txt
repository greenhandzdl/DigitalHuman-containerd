# FunASR 容器的依赖集 —— 不改动任何上游仓库，本文件只存在于 containerd/overlay/。
#
# 这一份为什么不是照抄伙伴方那个镜像：`docker history careecho-integrated-dockerd-funasr:latest`
# 量到的是 `pip install websockets funasr modelscope numpy` + 一层 CPU 的 torch/torchaudio
# —— **一个版本都没钉**。它跑起来是好的，但"哪天 pip 解析到别的东西"这件事没人负责。
# 这里钉的是那台镜像里实测在跑的六个版本号（`docker run --rm --entrypoint pip list` 读出来的），
# 也就是"照着已被验证的组合钉"，不是"照着最新钉"。funasr 现在已经出到 1.4.x，
# 升级要连同模型 revision 一起验，不能靠一次无钉的 `pip install` 顺手完成。

# 识别本体。funasr 1.3.x 的 AutoModel(model='paraformer-zh') 走 modelscope 的别名表，
# 1.4.x 改过这套映射，所以不追新。
funasr==1.3.14
modelscope==1.38.1

# 装的是 CPU 版（torch==2.13.0+cpu / torchaudio==2.11.0+cpu 在 images/funasr.Dockerfile 里
# 单独一层从 download.pytorch.org/whl/cpu 装 —— 那里才有 +cpu 后缀的 wheel，
# 而 PyPI 默认的 torch 是带 CUDA 运行库的，白多两 GB 且这台机器显存已满）。
# numpy 与 funasr/torch 这一组版本是互相验过的（2.x 系列）；裸装会跟着 funasr 的
# 依赖声明漂移，所以钉在它当时用的那个号上。
numpy==2.2.6

# WS 服务端。钉 16.1 有两个原因：① 伙伴方那台镜像就是 16.1，H5 客户端是照着它调通的；
# ② `serve()` 的 handler 签名在 14.0 从 `(websocket, path)` 变成 `(websocket)`，
# 与 Fay 镜像那边学到的教训同一类（uvicorn/websockets 的版本对不上，协议就直接不监听）。
# asr/server.py 两头都吃（path 给默认值），但钉住才谈得上可复现。
websockets==16.1
